# How `@sfotty-pie/spasm` works

Notes on the internals of the assembler, for contributors and AI agents. This is the package-scoped peer of the repo-wide [CONTRIBUTING.md](../../CONTRIBUTING.md): the readme is for _users_ of the library; this file is for people working _on_ it. It explains the approach and the moving parts; the per-function details live in doc comments next to the code.

## What it is

spasm is a multipass 6502 assembler. The defining choice is that **assembly and linking are one integrated, multipass engine** rather than separate tools: addressing-mode sizing (zero-page vs absolute), span-dependent branch offsets, and segment placement all feed each other, so they're resolved together by iterating to a fixpoint. There is no separate object-file/link step - a build is one or more source modules assembled together into final bytes.

The opcode table is **documented opcodes only** (it's generated as the inverse of the sibling [@sfotty-pie/sfotty](../sfotty) disassembler's `NMOS_OPCODES`). The eventual language is large (macros, a type system, conditionals, relocation); what's built today is tracked in [What's deferred](#whats-deferred).

## The pipeline

```
source -> lex -> parse -> +------------- multipass loop -------------+ -> bytes
                          | collect (evaluate + encode) -> render    |
                          +------------------------------------------+
```

1. **Lex** ([src/lexer.ts](src/lexer.ts)) - a single big anchored regex turns source into tokens.
2. **Parse** ([src/parser.ts](src/parser.ts)) - recursive descent for statements, a Pratt parser for expressions, producing a CST-ish AST that keeps its tokens (and trivia) for a future pretty-printer.
3. **Load** ([src/loader.ts](src/loader.ts)) - resolve and parse the `.import` closure into a module graph.
4. **Resolve anonymous labels** ([src/macros.ts](src/macros.ts), `resolveAnonymousLabels`) - number every lone `:` and rewrite the `:+` / `:-` references that point at them (see below).
5. **Scope local labels** ([src/macros.ts](src/macros.ts), `scopeLocalLabels`) - a static rewrite qualifying each `@name` with the label that owns it (see below).
6. **Expand macros** ([src/macros.ts](src/macros.ts)) - a static rewrite of every module's statements before assembly; macros are visible across modules via `.export .macro` and expansion is hygienic (see below).
7. **Scope `.if` arms** ([src/macros.ts](src/macros.ts), `scopeIfArms`) - another static rewrite: names defined inside `.if` arms rename to arm-locals, so the outside-visible definition set is pass-invariant while arm selection iterates (see Conditional assembly).
8. **Assemble** ([src/assemble.ts](src/assemble.ts)) - the multipass loop: each pass _collects_ content into segments (evaluating expressions, selecting `.if` arms, and encoding instructions) and then _renders_ the OUTPUT segment to bytes, until the symbol table reaches a fixpoint.

Steps 1-7 happen once; step 8 iterates.

## Public API surface

Everything exported lives in [src/index.ts](src/index.ts):

- `assemble(source, name?): AssembleResult` - assemble a single source string (no imports). **Synchronous** (no `Host`, so no I/O).
- `assemble(entry, host): Promise<AssembleResult>` - assemble a project rooted at module id `entry`, reaching other modules through a `Host`. **Asynchronous**, because the host is.
- `AssembleResult` - `{ output: Uint8Array, symbols: Map<string, Value>, definitions: Map<string, Definition>, references: Map<string, Reference[]>, moduleScopes: Map<string, ModuleScope>, diagnostics: Message[] }`. `output` is meaningful only when `diagnostics` is empty.
- `ModuleScope` - per-module visibility (`{ splats, bindings, exports, macroExports }`), for scope-aware tooling: completion needs "what can this file see" (own symbols, splat exports, bindings) and "what does this module offer", which `definitions` alone can't answer - it has no exported-ness and no import structure. `DOT_KEYWORDS` and `OPCODES` are exported for the same audience.
- `Definition` - a symbol's definition site and converged value (`{ file, start, end, kind, value }`), keyed in `definitions` by qualified name (module `SEP` name, the `Message.symbol` spelling; `SEP` is exported). Unlike `symbols` (entry module, resolved values only), `definitions` covers every module and includes unresolved and function-valued symbols. The file is derivable from the key's module prefix because spans and scope always agree: every definition's span indexes the source of the module it defines under - macro hygiene stamps renamed body-locals with the macro's module for exactly this reason (see Macros).
- `Reference` - a resolved reference (`{ start, end, symbol }`), keyed in `references` by the file the span indexes; `symbol` is a `definitions` key. Recorded by the converged pass's evaluator - the one place every name actually resolves, so locals, `.if`-arm renames, splats, and namespaced paths all come out right by construction rather than by a parallel resolver. `::` paths record per segment: on `cio::Command::OPEN`, the `cio` token maps to the binding, `Command` to the export, and `OPEN` to the dictionary entry - entry navigation works because a dict literal also defines its entries as table symbols under qualified names, spanned by their key tokens (literal site only: an alias or computed dict carries the value, not the names). `.import` specifier strings reference the imported module, which gets a synthetic kind-`"module"` definition at its file top (keyed by bare module id - collision-free, qualified names always contain `SEP`). Code macros never reach the symbol table, so expansion collects their navigation itself (`MacroNav` in [src/macros.ts](src/macros.ts)) under a double-`SEP` key namespace: `.macro` names and params get kind-`"macro"`/`"parameter"` definitions, call sites reference the macro (both segments, for `ns::name` calls), and param occurrences reference their params at the body spans - recorded _statically at collection_ (`recordParamUses`, mirroring substitution's traversal, expression-macro-def shadowing included), so uses are known for uncalled macros too. Together `definitions` and `references` are the language tooling's substrate: position-to-definition is a span lookup in `references` (or `definitions` when the cursor is on the definition itself), and find-references is the inverse.
- `Host` - `{ resolve(specifier, fromId): string | Promise<string>; read(id): string | Promise<string>; shortName?(id): string }` (re-exported from the loader). `resolve`/`read` may throw (or reject); the loader turns that into a diagnostic. `shortName` is the optional display name for formatted diagnostics (the CLI passes cwd-relative paths when shorter); ids stay canonical in `Message.file`.
- `Message`, `Value` - the diagnostic and value types.
- `Codes` - the diagnostic code registry ([src/codes.ts](src/codes.ts)): every `Message.code` is one of these stable, append-only `SPxxxx` identifiers (match on the code, not the message prose). Symbol-related diagnostics also carry `Message.symbol` (the qualified name, NUL-joined) for tooling.

**Sync core, async edge.** The `Host` is the only I/O and is consulted entirely upfront - `loadModules` (the loader) is the single async boundary, awaiting `resolve`/`read` while building the module graph. Everything after the graph is built (macro expansion, the multipass) is synchronous and shared by both entry points; the single-source overload just builds a one-module graph by parsing in-process, with no async at all. This keeps lexer/parser/evaluator/encoder sync and ready to port to a web or URL-backed host by swapping the `Host` alone.

A thin CLI ships too ([src/cli.ts](src/cli.ts), `bin: spasm`): `spasm INPUT -o OUTPUT`, parsing args with `node:util` `parseArgs` over an async `node:fs/promises` host.

## The multipass fixpoint

This is the core idea, and everything else is arranged to serve it.

A 6502 program can't be assembled in one linear pass: `lda foo` is 2 bytes if `foo` is in zero page and 3 if it isn't, but `foo`'s address depends on the sizes of everything before it. spasm resolves this by **iterating**:

- **Evaluate against the previous pass.** Within a pass, every expression resolves names and segment bases from the values the _previous_ pass produced. The first pass sees everything as unresolved.
- **Pessimistic, shrink-only sizing.** An unresolved operand is sized at its largest (absolute); once its value is known it can only shrink (to zero page). Monotone shrinking converges, and every intermediate state is a _valid_ program - so a non-converging build can still emit valid (if suboptimal) bytes.
- **Converge on symbol AND byte stability.** A pass snapshots the symbol table, runs, and compares - and the output bytes must also match the previous pass's. Symbols alone miss non-symbol state that feeds bytes (segment bases, `*`-relative `.res` counts, and iterative-`.if` arm flips, which are emit-only and often symbol-invisible); bytes alone would stop early on placeholder streaks while values are still propagating one hop per pass. Each side catches what the other can't see: emplaced segments contribute no bytes but move labels. The cap (statement count + 1, min 8) is a backstop, not the normal exit; overshooting emits a warning, not an error.

The symbol table ([src/symbols.ts](src/symbols.ts)) is built for this: values **persist across passes** (so a forward reference resolves to last pass's value rather than clobbering to `undefined`), while a per-pass "seen" set enforces **define-once** (a second definition in the same pass is the error; the first is kept). `undefined` means "not resolved yet," distinct from `has()` ("defined, regardless of value").

## Values and evaluation

`Value = bigint | string | FunctionValue | DictValue` ([src/value.ts](src/value.ts)); `undefined` threads through as "unresolved." **Dictionaries are ordinary values**: `N = { OPEN: 0, CLOSE: 2 }` evaluates to a `DictValue` whose entries are held inline as `Value | undefined`, so a dict with an unresolved entry is still a dict - only that entry is missing. They alias (`M = N`), pass through macro parameters, and nest. Dict literals take `:` (the call-site association mark - a keyword-arg list is a braceless dict literal; `=` inside braces would parse as equality), allow newlines as entry separators, reserve register names as keys like everywhere else (a future namespace-splat must be able to turn any key into a bare symbol, so keys and scope names share one name grammar - write `A4`, not `A`), and are immutable and statically keyed. A dict is a value but not an address (`:=` rejects it) and not data (`.byte N` is an error). Because keys are static, a **missing key is a hard error** at the access site, distinct from a key whose value hasn't resolved yet - which is an ordinary undefined symbol. A dict may not contain itself (`N = { A: N }` would nest a level deeper per pass); reaching a sibling through the root (`N = { foo: 1, bar: N::foo + 1 }`) is fine and settles through the fixpoint, in either order.

**`::` is value-directed** ([src/evaluate.ts](src/evaluate.ts), `resolvePath`): a path resolves its root, then indexes the remaining keys into the resulting value. The root is either a symbol in scope or a _namespace binding_ (`lib = .import "m"`), which is not itself a value and spends its first key reaching an export of the bound module; everything after that is plain value indexing, which is what makes `lib::N::V` chain into an exported dict. Making namespace bindings dict values in their own right is the remaining step (see What's deferred).

**Aggregates take part in convergence.** `SymbolTable.changedSince` compares with `isEqual` rather than `!==`, because a dict is rebuilt every pass (identity would always differ) and because a change can be _in flight_ inside one: with `.byte M` / `M = N::A` / `N = { A: LATER }` / `LATER = 7`, there is a pass where the bytes and every scalar are unchanged and the dict is the sole carrier of the change. Skipping aggregates there converges early and reports `M` undefined - there's a regression test for exactly that. Dict equality is structural and order-insensitive (a record's identity is its contents); functions compare by identity; construction caps nesting depth, which bounds the recursion and backstops mutual bare references across two dicts.

Numbers are unbounded `bigint` (range is checked at emit, not during arithmetic). Strings are first-class values, decoded with minimal C escapes; a **character literal is a single _byte_** in the target encoding (UTF-8 for now), so `'A'` is `65` but `'ü'` (two UTF-8 bytes) is an error - char and string literals share one encoder.

[src/evaluate.ts](src/evaluate.ts) is a straightforward recursive evaluator over an `EvalEnv` (`resolve`, the `*` location counter, `report`, `strict`). `resolve` takes an optional `origin` - the module a macro-stamped identifier lexically binds to (see Macros). `*` is also source-level syntax - an expression can reference the current location counter directly (`jmp *`). `undefined` propagates through arithmetic so forward references defer cleanly. With `strict` on (the assemble pass turns it on), an unresolved _identifier_ is reported as undefined - but only on the converged pass survives, since earlier passes' diagnostics are discarded. Equality is `=` (ca65-style, no `==`); precedence low->high is `|| < && < (= != < >) < (+ - |) < (* / % ^ & << >>)` - the ca65 split puts `|` with the additive operators and `& ^ << >>` with the multiplicative ones - with prefix `+ - < > ! ~` binding tightest and `::` (scope resolution) tighter still. `~` is the arbitrary-precision complement (`~$0C` is `-$0D`; byte/word truncation yields the expected `$F3` by arithmetic). Gotcha: `<<` lexes greedily, so comparing against a low byte is `a < <b` - the space matters (same tension as ca65).

**Operand values.** A shaped instruction operand is a first-class value (`OperandValue`, shape + wrapped value): constructor builtins make them (`.immediate_operand(3)`, nullary `.a_operand()`/`.x_operand()`/`.y_operand()` - the indirect pair's word order encodes operation order, `x_indexed_indirect` = `(v,x)`, `indirect_y_indexed` = `(v),y`), and a _shaped_ macro argument in expression position splices as one (previously an error, so nothing legal changed meaning; bare arguments keep splicing as plain expressions, so value predicates apply to them directly). There is deliberately no `.simple_operand` constructor - a plain value already is one. In operand position an operand value _becomes_ that operand (`lda .immediate_operand(3)` is `lda #3`; nesting inside a shaped operand is an error); in expressions it can be stored, compared, and introspected but not used in arithmetic or as data. Equality (`=`/`!=`) is structural for every value kind - same-kind only, a mixed comparison is a hard error (the typo-net stance) - which makes `channel = .immediate_operand(0)` the idiomatic dispatch. Introspection: `is_`-prefixed shape predicates mirror the constructors plus `.is_simple_operand`; value predicates `.is_integer`/`.is_string`/`.is_dictionary`/`.is_function`/`.is_operand`; `.operand_value()` unwraps (registers wrap nothing - error). Predicates defer while their argument is unresolved (a forward constant may yet resolve to an operand). There is deliberately no `.is_defined` (definedness flips across passes). Bare `x`/`y` parse as register operands but no instruction accepts one (and no `lda x` -> `txa` aliasing: the transfer matrix has flag and encoding holes - `ldx y` has no NMOS encoding - so register-adaptive moves belong to a visible library macro); they exist as macro-argument currency. Deferred together: `.operand_shape()` and `.typeof()` string accessors, arriving with the `spasm:` enum-dict story that makes string comparison typo-safe.

**Expression macros** are function-valued symbols, and their params are `parameter`-kind table symbols under the function's qualified name (`SCALE SEP v`, like dict entries) with body occurrences recorded as references at definition time - so rename, find-references, and unused detection cover them (a path can't reach them: the function root fails dict traversal before the namespace fallback). `DOUBLE(v) = 2 * v` defines one (the parser speculates on `(` after a statement-position identifier and backs out to the instruction parse when the shape isn't `params) =`), and `DOUBLE(2)` applies it (an identifier or `::` path hugging `(` is a call). The `FunctionValue` joins the `Value` union, interned per definition site so the fixpoint's identity comparison converges; the only operations are application and assignment aliasing (`D = DOUBLE`). Application is eager (args evaluate in the caller's scope), hygienic (body free names resolve in the defining module, by defaulting the origin), pure, and depth-capped against runaway recursion. Function params shadow code-macro substitution inside bodies. Functions are rejected as data, operands, and attribute values, and are filtered out of the public `symbols` map.

## Instruction encoding

[src/encode.ts](src/encode.ts) maps an instruction's operand _shape_ (immediate, indexed, indirect, ...) plus its evaluated value to an addressing mode, then to a byte, using the generated `OPCODES` table as the oracle (if a mnemonic lacks a mode, that's the error). Zero-page/absolute selection is the shrinkable decision: unresolved or >= `$100` -> absolute; a resolved value < `$100` with a zp form available -> zero page. Branch offsets are relative to `pc + 2`; range checks (byte, word, branch) fire at emit. An unresolved operand emits correctly-sized zero placeholders so later passes can fix it up.

## The segment / OUTPUT layout engine

This is what makes "assembler = linker." It lives in [src/layout.ts](src/layout.ts) and the `collect`/`render` split in [src/assemble.ts](src/assemble.ts).

**Segments are byte-collectors.** A `Segment` is an ordered list of _items_: literal `bytes` (from instructions and `.byte`/`.word`), an `.org`, a `label` (resolved later), a `res` (its count expression, evaluated at render), or an `emit`/`emplace` of another segment. The "current" segment (default `OUTPUT`, switched by `.segment "X"` or the shorthands `.code`/`.rodata`/`.data`/`.bss`/`.zeropage`, which upper-case into the segment name) receives content as collection walks the statements. `OUTPUT` is not special-cased - it's just the segment written to the file at the end.

**Collect -> render, per pass:**

- _Collect_ walks statements into segments, evaluating expressions and encoding instructions against the previous pass's symbol values and segment bases. Constants (`=`/`:=`) are defined here. Labels are recorded as items (their addresses aren't known yet).
- _Render_ (`render(segments, "OUTPUT", ...)`) walks the OUTPUT segment with two counters - a **location counter** (run address; set by `.org`, advanced by content/emit/emplace) and the **file length** (advanced by content/emit, _not_ by `.org`/`.emplace`, so run addresses and file offsets diverge cleanly). It recurses through `.emit "X"` (render X at the current LC, splice its bytes) and `.emplace "X"` (same, but reserve without emitting). Reaching a label item resolves it to the current LC; reaching an emit assigns that segment its **base**. A `res` item evaluates its count at the current LC (via an injected evaluator callback, same layering as label definition), so `*`-relative fills like `.res $2000 - *` are exact even on the first pass - the zeros ride the normal bytes path, so emit-vs-emplace needs no special casing. Collect can't know the size (it would bake the previous pass's base), so render feeds resolved sizes back (`resSizes`, like `bases`) and collect's running location advances by the previous render's size - one pass of lag the fixpoint absorbs, kept honest by byte-stable convergence. A negative count reports "content overflows the fill boundary." Cycles in the emit graph are detected (a stack set) and reported, not followed.

**Segment sanitation.** Every defined segment must be consumed - placed by `.emit`/`.emplace` somewhere or deliberately dropped with `.discard` (the typo net: a stray `.segment "CODW"` errors instead of silently orphaning bytes; "discarded but also placed" and duplicate discards are their own errors). Checked per pass in `assembleModules` from collect's `firstSeen`/`discards` bookkeeping, so `.if`-gated placement participates naturally. And emplaced content may only _reserve_: render threads an `emplaced` flag down the placement tree and rejects byte-emitting items (instructions, `.byte`/`.word` - their items carry spans for this) and nested `.emit`s, whose bytes could never reach the file. Labels stay _legal_ in a discarded segment (the null-segment configuration needs the same text to be placeable or discardable), but they're never rendered, so a live reference errors as an ordinary undefined symbol - post-convergence, those diagnostics (and "exported but never defined" ones) get notes pointing at the label and the discard site. The matching is structural, not textual: the diagnostic's `code`/`symbol` fields plus `Scopes.resolutionTarget` re-run the reference's scope resolution, so same-module, splat-import, and namespaced references all annotate, and an unrelated same-named symbol never does.

**The segment stack.** `.segment` takes any string-valued expression, `.segment()` in expression position is the current segment's name, `.push expr` pushes a value onto a per-module stack, and `.pop` (an expression) takes it back - so `.push .segment()` / `.segment .pop` is the save-switch-restore idiom, ca65's `.pushseg`/`.popseg` as a composition of orthogonal pieces. The stack is per-pass state: collect resets and replays it each pass, so the balance checks (an unpopped value at end of module, a pop past the top) are per-pass and only the converged pass's reports survive - an `.if`-arm flip mid-convergence settles silently. `.pop` is the language's one side-effecting expression, so its evaluation count must be deterministic: it is banned inside expression-macro bodies (evaluated per application, and pure by design), in `.if` conditions (later arms evaluate only when earlier ones fail), and in render-time `.res` counts (the collect-time stack is gone) - `EvalEnv` simply omits the hook there. `.segment()` reads ambient state like `*` and is available wherever `*` is, except `.res` counts. A segment name expression must resolve when the statement is reached (bytes have to go somewhere - there is no pessimistic fallback); the motivating forms always do. Macro bodies compose naturally: the stack belongs to the module being collected, so a balanced body saves and restores its caller's segment.

**Labels resolve as `base + offset`.** A segment's labels are offsets within it; render assigns the segment a base where it's emitted, and the label's absolute address is `base + offset`. Conceptually a label is the expression `.base("SEG") + offset` - it collapses to an absolute number once an `.org` anchors the emit chain (which, for the current samples, is immediate). The reverse, "stays symbolic until anchored" (true relocation), is deferred.

**Forward-segment references converge via the one-pass lag.** OUTPUT's header can reference a label (`.word start`) in a segment emitted _later_ in the same render. Because everything evaluates against the previous pass's values, the reference reads last pass's address and settles over passes - the same mechanism as ordinary forward labels. Branch pc is handled the same way: collect tracks a per-segment running location starting at the previous render's base, and same-segment branch offsets are base-invariant, so they converge regardless of the base.

## Modules and scoping

A build is a graph of modules reached through a `Host`. The loader ([src/loader.ts](src/loader.ts)) starts at the entry, resolves each `.import` (relative to the importer), parses it, and recurses - **deduped by canonical id** (a diamond loads once), in dependency order (imports before importers), with import cycles reported rather than followed. It records each module's resolved imports for scoping. `.import` evaluates the _whole_ module (any top-level side effects run); there is no `import type`-style exports-only form - though a module like lib.s that only exports assignments and macros has no side effects left to run.

Scoping ([src/scopes.ts](src/scopes.ts)) layers per-module scopes and one ambient scope over a single `SymbolTable` via qualified keys (`moduleId \0 name`; the ambient scope uses a reserved pseudo-module id). The rules:

- A module's symbols are **private** unless `.export`ed. Four export forms: `.export name = expr` / `name := expr` (exported definition), `.export name(params) = expr` (exported expression macro), `.export name:` (define a label here and export it), and bare `.export name` (export a definition made elsewhere in the module; a name never defined anywhere is an error after convergence). A symbol may be exported only once per module.
- `.import "m"` is a **splat**: `m`'s exports become resolvable in the importer. Resolution checks the module's own scope, then its splat-imports' export sets.
- `lib = .import "m"` is a **namespaced import**: the module's exports bind to `lib` - `lib::FOO` for symbols (chaining into exported dicts: `lib::N::V`), `lib::mva args` in statement position for exported macros (a path is necessarily a macro call - no opcode has `::`). Nothing splat-leaks; the binding name is define-once in the importer's scope; bare `lib` is not a value (making it one - a dict of the module's exports - is a deferred step). A macro body's namespaced references and calls resolve through the _defining_ module's bindings (lexical, like everything else).
- There is **no ambient/global scope**. The entry-point handshake is an exported macro: the format module exports (say) `output_sfotty_exe start`, the program calls it passing its entry label, and after expansion the `.word start` in the format script is an ordinary intra-module reference in the program - no cross-module value flow, no extra pass.

Because labels are defined during _render_ (when addresses are known) but belong to a specific module's scope, each label item carries its `moduleId`, and render defines it via `scopes.defineLocal(moduleId, ...)`.

## Macros

**Anonymous labels** (`resolveAnonymousLabels` in [src/macros.ts](src/macros.ts)) run first, and are the only pass that cares about _position_ rather than names: a lone `:` is parsed as a label carrying the placeholder name `:`, and each `:+` / `:-` as an identifier spelled with its signs, so no new AST shapes are needed - the resolver just renumbers definitions to `:0`, `:1`, ... and rewrites references to match. Numbering is per _context_: a module's top level, or one macro body, so a body's anonymous labels are unreachable from the call site and vice versa (hygiene then makes them unique per expansion). `.if` arms are not contexts - numbering stays lexical, so it can't depend on which arm wins - but arm-local visibility applies afterwards like any other name. The parse has one subtlety: a sign must _hug_ the colon, and `identifier :` speculates one token past the colon to see it, because `bne :+` would otherwise parse as a label named `bne`. That adjacency rule is also what keeps `size: -1` and a dictionary's `KEY: -1` keyed entries with negative values - there the entry rule consumes the colon before the expression parser ever sees it.

**Local labels** (`scopeLocalLabels` in [src/macros.ts](src/macros.ts)) are the third static rewrite, and the first to run. A `@name` is qualified with the nearest preceding non-local label (`read_word@eof`), so define-once, forward references, and scoping all come from the existing symbol machinery rather than a parallel mechanism. Locals written before any label get a module-initial owner spelled `@`, so they qualify to `@@name`. Both forms are unspellable, which is what makes an escaped reference fail: a name that isn't in its scope's definition set is left alone, so it resolves to nothing and reports as the `@name` the author wrote instead of a mangled one. Two boundaries are deliberate. **`.if` arms neither open nor close a scope** - an arm belongs to the scope in effect at the `.if`, so arm selection can never change what a local means, the same pass-invariance `scopeIfArms` protects (arm-_local visibility_ still applies afterwards, since the qualified name is renamed like any other arm definition). **Macro bodies are skipped**, which falls out for free because `substituteStatement` has no `macro` case: a body's `@name` is renamed per expansion by macro hygiene, which already makes it unique and unreachable. Running before expansion is what keeps the two apart - it means a macro call can't silently re-point the caller's local scope, and an expanded body can't capture the caller's locals.

Macros are a static, syntactic step ([src/macros.ts](src/macros.ts)) that runs once _before_ the multipass - `expandModules` collects every module's `.macro name params ... .endmacro` definitions (removing them from the stream), then replaces each call - an instruction whose mnemonic names a visible macro - with the body. Visibility mirrors symbol scoping: a module sees its own macros plus the **exported** (`.export .macro`) ones of its imports, and a body's own macro calls resolve where the macro was _defined_, not where it was called.

A macro call takes a comma-separated **operand list** - a comma followed by a register name binds to the preceding operand as its indexed suffix (registers are reserved words, so this is unambiguous), any other comma separates operands - and each argument is a whole _operand_, shape included: `mva (src),y, (dst),y` passes two indirect-indexed operands. Operand is a **super-type of simple values**: a simple operand (a plain expression) substitutes anywhere; a shaped operand (immediate, indexed, indirect, accumulator) substitutes only where a param stands alone in operand position (`lda src`), and using one inside an expression is a type error at expansion. (Future introspection builtins - `.mode()`/`.value()` - will open shaped operands up to advanced macros.) Real mnemonics reject operand lists with an arity error at encode.

Expansion is hygienic with **lexical binding**. Per call, the body is `structuredClone`d (so the template isn't mutated) and each identifier is classified three ways: a _param_ substitutes to its argument operand (the caller's binding - params are the only call-site channel); a name _defined_ in the body (labels, `:=`/`=`) renames with a per-expansion suffix (`name@N`) so repeated calls don't collide - and is origin-stamped like a free name, so the renamed local lives in the macro's module, where its token spans point (definition-site queries and diagnostic attribution rely on span and scope agreeing, and gensym'd locals stay out of the caller's public `symbols`); mnemonic tokens are stamped too, marking the statement as expanded - encode-time value errors span the operand _expression_ and attribute via `getExpressionOrigin` (the leftmost token's origin, so a spliced call-site argument squiggles at the call site), and when that lands in a different file than the body, the diagnostic narrates the whole expansion path, outermost first, via two chains that meet at the error: the statement's `expansionTrail` (each cloned body statement chains its call sites) names the macros, and the operand's splice chain (`Token.substitutedAt` on the expression's anchor token - each argument splice appends the param occurrence it replaced) supplies the spans, so every "While expanding" note underlines the failing value _as written in that macro's body_, falling back to the hop's call site where the value didn't pass through, and dropping a hop that would just repeat the error's own span; a _free_ name is stamped with the defining module's id (`Token.origin`) so it resolves in the defining module's scope - private helpers work in bodies without being exported, and the ca65-style "the includer defines the symbol" idiom is deliberately rejected. The outward channel is a declared contract: a `.out` param (`.macro alloc .out name`) receives its definition from the body (`name: .res 1`, `name = expr`, or forwarding to a nested call's `.out` position - reads are also allowed) and lands it under the caller's name in the caller's scope. Both directions are checked at the definition site, for used and unused macros alike: an `.out` param the body never defines is an error, and a plain param the body defines (or forwards to an `.out` position) is an error telling you to declare it `.out`. At the call, an `.out` argument must be a plain identifier - rejected at the call span otherwise. Nested calls expand recursively under a depth cap.

Free names of macros that are never expanded are still checked structurally at the definition site (a name must be defined in the defining module or exported by its imports); expanded bodies get the same check for free via the normal strict-mode undefined-symbol path, whose spans point at the body tokens. Module-level directives (`.import`/`.export`/`.macro`) are rejected inside bodies.

## Conditional assembly (`.if` / `.error`)

`.if`/`.elseif`/`.else`/`.endif` is the **iterative** conditional stratum: arm selection is re-decided every pass by `selectArm` in [src/assemble.ts](src/assemble.ts) (conditions read anything the layout knows - `*`, addresses, distances), and collect walks only the taken arm. Two decisions make it converge:

- **An unresolved condition skips its arm**, falling through to `.else` (or nothing) - and strict mode reports the unresolved names on the converged pass, exactly like an unresolved `lda sym` emits absolute and errors. The documented convention is therefore that **`.else` holds the pessimistic, always-correct form** (the `jne` macro's long `beq`/`jmp`), so selection only moves else -> specific as values settle - the branch-flip analog of shrink-only sizing. A condition written the other way can oscillate; byte-stable convergence plus the pass cap catches that with the non-convergence warning.
- **Arms are scopes** (`scopeIfArms` in [src/macros.ts](src/macros.ts), a static pass after expansion): a name defined inside an arm renames to a per-arm local (`name@ifN`), reusing the macro-substitution machinery, with nested arms shadowing. This makes the ghost-label hazard _unrepresentable_ - a definition can't flip in and out of the outside-visible set with an address-dependent condition, so the fixpoint never chases a moving definition target, and no per-pass symbol GC is needed (stale arm-locals in the table are unreachable, hence inert). The "whichever arm wins" idiom is a label on the `.if` statement itself; conditional _values_ use expressions (`size = 2 + (big > 255)`); a name defined in _every_ arm staying outside-visible is a noted possible future relaxation (it would still be pass-invariant). Arms are emit-only: `.import`/`.export`/`.macro` are rejected inside them, and macro params (`.out` included) may not be defined in an arm.

`.error expr` reports its (string) message when collected - unconditionally at top level, only in taken arms inside `.if` - and rides the existing converged-pass-only diagnostics, so address-dependent bounds checks (`.if * > $0100` / `.error "Zero page overflow"`) fire against the settled layout, never spuriously mid-iteration.

The exported-macro mechanism is also the **output-format channel**: lib.s exports `output_sfotty_exe start`, whose body defines the segments and the OUTPUT script; each program calls it once, passing its entry label.

## Syntax decisions worth knowing

- **`=` vs `:=`.** `name = expr` defines a _constant_; `name := expr` (and `name:`) defines a _label_ (address-valued). The kind is recorded on the symbol; it carries no behavior yet but is the hook for future address attributes.
- **`::`, not `.`, for dictionary/scope access.** A member dot would collide with the dotted-keyword lexing (`.byte`, `.word`), so access uses `::` (ca65-style): `NOTES::C4`. Resolution is value-directed (see Values).
- **Line continuation is `\` before the newline** (trailing blanks and a trailing comment allowed; a comment _before_ the backslash still swallows it). Lexer-level: the whole sequence is whitespace trivia, so the parser never sees the line break.
- **The register-name lexing trap.** Bare `a`, `x`, `y` lex as registers, not identifiers (so `asl a` is accumulator mode). Tests and sample code must avoid them as symbol names - a recurring gotcha.
- **Diagnostics carry their module and arrive pre-formatted.** `Message` is `{ type, code, start, end, message, file?, symbol?, notes?, formatted?, formattedColor? }`: every reporter threads a stable code from the `Codes` registry and the owning module id, and `assemble` renders tsc-style blocks (`file:line:col - type SPxxxx: message`, then the source line behind a line-number gutter with `~` squiggles under the span) via [src/source-file.ts](src/source-file.ts). `formattedColor` is the same block with ANSI colors (file cyan, line:col yellow, kind + squiggles in the kind's color, gutter inverse) - consumers pick it when stderr is a tty (and `NO_COLOR` is unset), as the CLI does. `notes` are secondary spans (`MessageNote` - no nested notes), rendered as `note:` blocks of the same shape after the message: "First defined here" on duplicate symbols/macros/exports/attributes, "First placed here" on double placement, and "While placing X" / "While importing X" chains on emit and import cycles. Attribution rides hygiene: an error on a macro-body token carries the body's `origin`, so it points into the macro's file, not the call site's. Consumers print `formatted ?? message`.

## The opcode table

[src/opcodes.ts](src/opcodes.ts) is **generated and committed**: `mnemonic -> { mode: byte }`, documented opcodes only. [src/generate-opcodes.ts](src/generate-opcodes.ts) (dev-only, `pnpm --filter @sfotty-pie/spasm generate:opcodes`) imports the sibling sfotty core's `NMOS_OPCODES` _source_ directly (no package dependency), inverts it, filters undocumented opcodes, asserts the inverse is faithful, and prettier-formats the output. Treat `opcodes.ts` as pure output.

## What's deferred

All four samples (hello/echo/cat/guess) now assemble and run. Not yet built (roughly in priority order - **nicer diagnostics** is the highest-value next step now that there's a CLI):

- **The static `#if` stratum** - hash conditionals decided once, pre-fixpoint, that may alter structure (gate imports/exports/macros); prelude-ordered imports come with it. (The iterative `.if`/`.elseif`/`.else`/`.endif` + `.error` are done - see Conditional assembly.)
- **Segment attributes** (`.define_segment "X", type:..., executable:...`) - the kind/exec flags and their keyword-arg syntax; emit-vs-reserve is currently chosen by `.emit`/`.emplace` alone.
- **Relocation** - symbolic `.base()`/`.reloc`, and the `.base`/`.startof`/`.sizeof` builtins.
- **Symbol attribute semantics** - the `:=` keyword tail (`X := $D300, size: 256`) parses and its shape is checked (labels only, `size` the only key, given once), but the value is never evaluated and nothing is stored; `.attributes()`/`.sizeof()` were removed along with it. What an attribute means depends on the address-vs-number split below, so the syntax is reserved and inert until that lands. Libraries can be written against the final spelling today.
- **Addresses as a value type** - label-vs-constant still lives on the _binding_ (`SymbolKind`) rather than the value, so `C = L` launders an address into a plain number. Making an address a value (carrying its relocation base and its attributes) is what would let attributes survive arithmetic, give relocation the address/constant distinction it needs at each emit site, and - together with dicts, which already retired the `namespace` kind's only job - let `SymbolKind` go entirely. `SymbolTable.kindOf` currently has no callers.
- **Namespace bindings as values** - `lib = .import "m"` binds a name that `::` reaches _through_ (structurally, via the module's export set) rather than a dict value of the module's exports. Making it a value would let a module namespace be aliased and passed around like any other dict, and would collapse the two-step root resolution in `resolvePath` into plain indexing.
- **Aggregates beyond dicts** - a list type (ordered, positionally indexed) for `.for` iteration and rest parameters, with `{}` as a single transparent empty that satisfies both shapes. Operands as values (six wrapper types over a transparent "simple") wait on construction syntax.
- **Mutual dictionary cycles** - `N = { A: M }` / `M = { B: N }` nests a level deeper each pass. The self-reference check only sees a literal naming itself, so this is caught by the depth cap or the pass cap rather than by a precise diagnostic, alongside the cyclic-definition gap below.
- **Richer modules** - named/aliased imports (`.import "m": a, b` and aliases) and the `.namespace ... .endnamespace` inline-module block. (Dict-valued symbols, `::` access, namespaced imports `name = .import "m"` - macros included - and the label/bare export forms are done.)
- **Richer macros** - keyword arguments and defaulted params, operand introspection builtins (`.mode()`/`.value()`), and exporting macro-defined symbols beyond the param-named-definition channel (fixed-name or derived names like `name_end`).
- ~~**Diagnostic polish**~~ - done: tsc-style formatting with source excerpts and squiggles, multi-span notes ("previously defined here" and cycle chains), `shortName` shortening (cwd-relative in the CLI), and colorized tty output.
- **Cyclic _definition_ detection** - `A = B` / `B = A` converges to undefined and reports "undefined symbol" (no hang), not a precise cycle error.
- **A pretty-printer / formatter** - the parser keeps every token and its trivia precisely so the AST can round-trip back to source; nothing consumes that yet.
